# 02. 프로젝트 목록

> 상태: 작성 중 (2026-10-27)
> 회사 재정의 2단계. 부서마다 지금 하고 있거나 하고 싶은 일을 모으고, 일의 단위와 생애 주기를 정한다. 3단계(업무 흐름)는 이 목록에 나온 일의 종류에서 흐름을 만든다.

## 1. 일의 단위 (초안)

부서마다 일의 모양이 달라서, 회사가 다루는 일을 세 단위로 나눈다.

| 단위 | 뜻 | 예 |
|------|----|----|
| 프로젝트 | 이름이 있고 오래 이어지는 일. 제품 하나, 학습 과정 하나 | 가게씨, 본업 앱, "Swift Concurrency 학습" |
| 정기 업무 | 정한 주기마다 반복하는 일 | 주간 IT 이슈 브리핑, 매일 메일 정리, 야간 시나리오 테스트 |
| 요청 | 한 번 하고 끝나는 일. 보통 프로젝트에 속한다 | 기능 하나 추가, 버그 수정, 정보 조회 하나 |

`[미결]` 이 세 단위로 나눌지.

## 2. 생애 주기 (초안)

### 2.1 제품 프로젝트

```
아이디어 → 기획 → 개발 → 출시 → 운영 → 종료
                 └──────── 보류 (어느 단계에서든) ────────┘
```

| 상태 | 뜻 | 들어가는 조건 |
|------|----|-------------|
| 아이디어 | Zero가 낸 생각. 팀장 의견을 모으는 중 | Zero가 등록 |
| 기획 | 기획팀이 기획서를 쓰는 중 | Zero가 신규 기획 승인 |
| 개발 | 첫 출시 전 개발 | Zero가 기획서 승인 |
| 출시 | 출시 준비, 스토어 제출 | Zero가 배포 승인 |
| 운영 | 출시 뒤 개선·유지보수 | 첫 출시 완료 |
| 보류 | 잠시 멈춤. 정기 업무도 멈춘다 | Zero 결정 |
| 종료 | 더 이상 다루지 않음 | Zero 결정 |

### 2.2 교육 프로젝트

목표 → 계획 → 진행 → 완료 (보류 가능). 성공 기준(학습 계획 이행률)은 "진행" 중에 잰다.

### 2.3 비서

비서 부서는 프로젝트보다 정기 업무와 요청이 중심이다. 정기 업무는 켜짐·꺼짐만 있다.

`[미결]` 생애 주기 상태 이름과 단계.
