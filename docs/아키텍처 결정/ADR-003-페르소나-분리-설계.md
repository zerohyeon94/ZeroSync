# ADR-003 — Alpha/Beta 페르소나를 별도 시스템 프롬프트로 분리

> 날짜: 2026-04-28 | 상태: 확정

---

## 결정

Alpha와 Beta를 **동일한 Claude API에 다른 시스템 프롬프트**를 주입하는 방식으로 구현한다.
각 페르소나는 독립적인 대화 히스토리를 가진다.

## 맥락

- 두 페르소나가 명확히 다른 성격과 말투를 유지해야 함
- 대화 맥락이 섞이면 페르소나 일관성이 무너짐

## 선택지

| 옵션 | 장점 | 단점 |
|------|------|------|
| **별도 시스템 프롬프트 + 독립 히스토리** | 페르소나 혼선 없음, 구현 단순 | API 호출이 두 배 (동시 응답 시) |
| 단일 프롬프트로 두 페르소나 동시 제어 | API 호출 1회 | 프롬프트 복잡, 페르소나 혼선 위험 |
| 별도 API 키 또는 별도 계정 | 완전 분리 | 비용 및 관리 복잡도 증가 |

## 구현 방식

```typescript
// alpha-client.ts
const alphaSystemPrompt = `
당신은 INTJ 성향의 AI 어시스턴트 '알파'입니다.
감정적 위로나 공감 표현 금지. 논리와 효율만 기준.
말투: 단호하고 짧게, 사족 없이.
`

// beta-client.ts
const betaSystemPrompt = `
당신은 ISFJ 성향의 AI 어시스턴트 '베타'입니다.
사용자의 컨디션과 일정을 최우선 고려.
친절하고 다정한 존댓말 사용.
`
```

## 트레이드오프

- Alpha와 Beta가 서로의 대화를 참조할 수 없음 (향후 공유 컨텍스트 추가 검토)
- 동시 응답 기능 구현 시 API 호출 2회 필요
