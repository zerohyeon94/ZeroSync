# 회사 재정의

ZeroSync를 "프로젝트 하나를 원격 관리하는 봇"에서 "여러 팀이 Zero의 일을 나눠 맡는 회사"로 다시 정의하는 문서 모음이다.
앞 단계의 결정이 뒷 단계의 판단 기준이 되도록 **목적 → 일 → 사람 → 운영 방식 → 시스템** 순서로 정한다 (2026-10-27 Zero 결정).

| 단계 | 문서 | 정하는 것 | 상태 |
|------|------|----------|------|
| 1 | [01-헌장.md](01-헌장.md) | 목적, 부서와 우선순위, 하지 않는 일·승인할 일, 성공 기준, Zero의 역할 | 확정 (2026-10-27) |
| 2 | [02-프로젝트.md](02-프로젝트.md) | 일의 단위, 생애 주기, 부서별 프로젝트 목록·상태·우선순위, 입력 경로, Discord 채널 구성 | 확정 (2026-10-27) |
| 3 | [03-업무-흐름.md](03-업무-흐름.md) | 제품 부서 일의 종류별 흐름, 채널, 승인 지점, 팀 역할, 디자인 형식, 먼저 만들 흐름 | 확정 (2026-10-28) |
| 4 | [04-조직.md](04-조직.md) | 제품 부서 조직도, 흐름별 담당, 새 팀장(Gamma, Delta) 역량·성격, 겸임, ADR-006 변경점 | 확정 (2026-10-28) |
| 5 | [05-운영.md](05-운영.md) | 제품 부서의 보고, 승인, 순서·동시 진행, 예산, 대시보드, 기록 위치, 정보 보호 | 초안 |
| 6 | ADR-007, SPEC 개정 | 위 결정의 시스템 반영, 로드맵, Phase 2 처리 | 예정 |

- 1~5단계는 문서만 쓴다. 구현은 6단계 이후로 미룬다
- 이 저장소는 공개다. 본업 회사 이름, 메일 내용처럼 공개하면 안 되는 정보는 여기에 적지 않고 비공개 저장소(`zerosync-company`)에 둔다
