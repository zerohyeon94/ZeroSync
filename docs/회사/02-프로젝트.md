# 02. 프로젝트 목록

> 상태: 작성 중 (2026-10-27)
> 회사 재정의 2단계. 부서마다 지금 하고 있거나 하고 싶은 일을 모으고, 일의 단위와 생애 주기를 정한다. 3단계(업무 흐름)는 이 목록에 나온 일의 종류에서 흐름을 만든다.
> `[미결]`은 Zero가 아직 정하지 않은 항목이다. 본업 앱의 이름·내용처럼 공개하면 안 되는 정보는 이 문서에 적지 않는다.

---

## 1. 일의 단위

부서마다 일의 모양이 달라서, 회사가 다루는 일을 세 단위로 나눈다.

| 단위 | 뜻 | 예 |
|------|----|----|
| 프로젝트 | 이름이 있고 오래 이어지는 일. 제품 하나, 학습 과정 하나 | 가게씨, 본업 앱, "Swift Concurrency 학습" |
| 정기 업무 | 정한 주기마다 반복하는 일 | 주간 IT 이슈 브리핑, 매일 메일 정리, 야간 시나리오 테스트 |
| 요청 | 한 번 하고 끝나는 일. 보통 프로젝트에 속한다 | 기능 하나 추가, 버그 수정, 정보 조회 하나 |

세 단위로 나눈다 (2026-10-27 Zero 결정).

---

## 2. 생애 주기

### 2.1 제품 프로젝트

```
아이디어 → 기획 → 개발 → 출시 → 운영 → 종료
                 └──────── 보류 (어느 단계에서든) ────────┘
```

| 상태 | 뜻 | 들어가는 조건 |
|------|----|-------------|
| 아이디어 | Zero가 낸 생각. 팀장 의견을 모으는 중 | Zero가 등록 |
| 기획 | 기획팀이 기획서를 쓰는 중 | Zero가 신규 기획 승인 |
| 개발 | 첫 출시 전 개발 | Zero가 기획서 승인 |
| 출시 | 출시 준비, 스토어 제출 | Zero가 배포 승인 |
| 운영 | 출시 뒤 개선·유지보수 | 첫 출시 완료 |
| 보류 | 잠시 멈춤. 정기 업무도 멈춘다 | Zero 결정 |
| 종료 | 더 이상 다루지 않음 | Zero 결정 |

### 2.2 교육 프로젝트

목표 → 계획 → 진행 → 완료 (보류 가능). 성공 기준(학습 계획 이행률)은 "진행" 중에 잰다.

### 2.3 비서

비서 부서는 프로젝트보다 정기 업무와 요청이 중심이다. 정기 업무는 켜짐·꺼짐만 있다.

위 생애 주기를 쓴다 (2026-10-27 Zero 결정).

## 3. 목록

Zero에게 받은 내용으로 채운다.

### 3.1 교육 (우선순위 1)

교육은 Zero의 Obsidian 볼트(`zerohyeon-labs`)에 md 파일을 쌓는 방식으로 하고 있다. 볼트 안의 학습 운영 방식은 Zero가 지금 정하는 중이다.

| 확인한 것 (2026-10-27) | 내용 |
|----------------------|------|
| 볼트 | 제품 부서가 기획·결정 노트를 쓰는 볼트와 같은 볼트다 (`bot/projects.yaml`의 `vault_projects`가 이 볼트의 `Projects/`) |
| 기존 운영 | 볼트의 `AGENTS.md`에 학습 지침이 있다. Codex가 Daily Note를 만들고 학습 코치, 진로 상담, 신기술 큐레이터, 프로젝트 파트너, 블로그 초안, 금융 기초 학습 보조를 맡는다. Zero가 직접 명령해 돌린다 |
| 학습 폴더 | 분야별 학습 노트(iOS, CS, 백엔드, AI 등), 매일 연습, 템플릿, 일일 정리 스크립트 |

| 프로젝트·정기 업무 | 상태 | 비고 |
|------------------|------|------|
| 볼트 학습 운영 | 계획 (Zero가 설정 중) | 회사가 이 방식을 이어받을지, 새로 만들지는 3단계 |

- 교육 부서는 새로 만드는 것이 아니라 볼트에서 이미 돌아가는 학습 운영을 회사로 옮기는 일에 가깝다
- 볼트의 학습 지침은 Codex 기준이고, ADR-006은 모든 에이전트를 Claude로 시작한다. 교육 담당의 엔진은 4단계에서 정한다
- 금융 기초 학습은 투자 추천 없이 개념 학습만 한다는 볼트 규칙을 그대로 따른다

### 3.2 비서 (우선순위 2)

| 정기 업무·요청 | 주기 | 비고 |
|--------------|------|------|
| IT 이슈 브리핑 | 매일 확인, 특별한 사건이 있는 날만 보고 | 예: 주요 AI 회사의 상장 신청, 주요 모델 출시. 볼트에 `Learning/IT Trends`, `Market Briefs` 폴더와 IT 트렌드 템플릿이 이미 있음 |
| 개인 메일 정리 | `[미결]` | 헌장 3장. 메일 계정·접근 방식은 5단계 |
| 지식·정보 조회 보고 | 요청 때마다 | 헌장 3장 |

- "특별한 사건"을 무엇으로 볼지 기준이 필요하다. 기준과 보고 형식은 3단계에서 정한다
- 볼트의 기존 학습 운영에도 "신기술 큐레이터" 역할이 있다. IT 이슈를 교육과 비서 중 누가 맡을지 3단계에서 정한다

### 3.3 제품 (우선순위 3)

| 프로젝트 | 종류 | 상태 | 비고 |
|---------|------|------|------|
| 가게씨 (GagaeSsi) | 개인 iOS 앱, 일일 예산 관리 | `[미결]` | ADR-005 파일럿 대상. 볼트 `Projects/일일 예산 관리 앱/` |
| 오롯 (FocusOps) | 개인 앱 | `[미결]` | 볼트 `Projects/FocusOps/` |
| 제이데이 (Jday) | 개인 앱 | `[미결]` | 볼트 `Projects/Jday/` |

- 제품은 위 세 개다 (2026-10-27 Zero 결정). ZeroSync 자체와 FocusSense는 제품 목록에 넣지 않는다
- `[미결]` 본업 앱. 헌장 3장에서 본업 지원을 제품 부서로 넣었는데 목록에는 빠져 있다
- `[미결]` 제품마다 상태와 우선순위
