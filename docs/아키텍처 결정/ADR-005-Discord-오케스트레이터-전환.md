# ADR-005 — ZeroSync를 Discord 멀티 에이전트 오케스트레이터(v2)로 전환

> 날짜: 2026-10-05 | 상태: 확정 | 근거 문서: [운영 규약](../운영-규약.md) | 설계: [SPEC](../SPEC.md)

---

## 결정

ZeroSync 저장소의 주 개발 대상을 v1 macOS 메뉴바 AI 비서 앱에서 **Discord 기반 멀티 에이전트 오케스트레이터 봇(v2)**으로 전환한다.

- 봇은 **Python 3.11+**로 작성하는 결정론적 프로그램이다. LLM이 아니며, 에이전트 출력의 정해진 JSON 블록을 검증해 옮길 뿐 해석하지 않는다
- 에이전트는 두 개다
  - Beta · Claude (ISFJ): 의견(설계·유지보수), 설계, 구현, 리뷰 반영, 문서 반영안
  - Alpha · Codex (INTJ): 의견(실행·위험), 리뷰, 판정
- 판단(방향, 설계 승인, merge, 문서 반영)은 Zero만 한다
- 외부(GitHub, Obsidian 볼트)에 쓰는 주체는 봇 하나다
- 워크플로 로직은 Discord에 묶지 않는다. 입출력은 `bot/discord_io/` 계층 뒤에만 둔다

역할, 권한, 단계, 기록 위치, GitHub 규칙의 세부 내용은 [운영 규약](../운영-규약.md)을 따른다.

## 맥락

- 개인 앱 저장소(가게씨, 오롯, 제이데이)의 기능 개발을 "의견 → 결정 → 설계 → 구현 → 리뷰 → merge → 문서 반영" 흐름으로 반복하고 있다
- 이 흐름에서 사람이 할 일은 판단뿐이고, 나머지(에이전트 호출, 테스트 실행, Issue·PR 작성, 볼트 기록)는 규칙대로 반복된다
- 작성자(Claude)와 검증자(Codex)를 분리해야 자기 작업을 스스로 승인하는 문제를 막을 수 있다
- 모바일에서 입력하고 알림을 받아야 하지만, 맥은 외부에서 접속할 수 없다

## 선택지

| 항목 | 선택지 | 결정 |
|------|--------|------|
| 인터페이스 | Discord / 자체 앱 | Discord. 모바일 입력, 푸시 알림, 외부에서 맥으로의 중계, 무제한 기록을 별도 구현 없이 확보한다 |
| 봇의 성격 | LLM 에이전트 / 결정론적 프로그램 | 결정론적 프로그램. 판단은 Zero, 내용은 에이전트, 전달·검증은 봇으로 나눈다 |
| 테스트 실행 | Codex가 재실행 / 봇이 실행 | 봇이 실행. Codex 읽기 전용 샌드박스에서 xcodebuild가 실패할 가능성이 있다 [검증 필요] |
| 에이전트 출력 | 자유 텍스트 / JSON 스키마 | JSON 스키마. pydantic으로 검증하고 저장·표시·옮겨 적기를 같은 원본에서 만든다 |

## 근거

- 결정론적 봇은 동작을 단위 테스트로 고정할 수 있다 (예: 멘션 여부를 이벤트 종류로 결정)
- 사실(테스트 결과)을 봇이 직접 확인하므로 에이전트의 자기 보고에 의존하지 않는다
- 입출력 계층을 분리해 두면 나중에 자체 앱이나 다른 메신저로 바꿀 때 워크플로 로직을 다시 쓰지 않아도 된다
- 상태와 에이전트 출력 원본을 SQLite에 두므로, 이후 메뉴바 대시보드(Phase 6)가 Discord를 거치지 않고 같은 데이터를 읽을 수 있다

## v1 앱의 처리

- v1 Swift 메뉴바 앱(ADR-004)은 삭제하지 않는다. 다음 스레드에서 `menubar/` 폴더로 옮긴다
- ADR-002(Claude API), ADR-003(페르소나 분리), 샌드박스 해제 ADR은 v1 앱에만 적용한다
- v1의 페르소나 정의(Alpha INTJ / ESTP 표기, Beta의 일정·번아웃 관리)는 v2에서 위 정의로 대체한다. Beta의 일정·번아웃 관리 기능은 v2 범위에서 제외한다
- [CONCEPT.md](../CONCEPT.md)는 v1 기획서로 남긴다

## 트레이드오프

- Discord 서비스와 웹훅 동작에 의존한다. silent 메시지 지원 등 일부 동작은 [검증 필요]
- Claude·Codex CLI 호출 비용과 사용량 제한을 봇이 관리해야 한다 (테스트 실패 시 Codex 호출 생략 등)
- 저장소에 Swift 앱과 Python 봇이 함께 있어 빌드·테스트 도구가 두 벌이 된다
- 운영 규약의 [검증 필요] 항목(CLI 스키마 강제 출력, 볼트 git 접근, 브랜치 보호 요금제 등)은 구현 전에 확인해야 한다
