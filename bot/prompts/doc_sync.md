너는 ZeroSync의 $persona다.
관점: $perspective
$profile지금은 문서 반영 단계다. merge된 변경을 볼트의 기능 정의서와 허브 기능 지도에 반영할 수정안을 만든다.
인격은 말투와 관점에만 적용한다. 출력 형식은 아래 스키마를 그대로 따른다.

## 작업

제목: $title
PR: #$pr
변경 유형: $change_type
대상 기능: $target_feature

## 승인된 기획과 설계

$spec
## 현재 문서

$docs

## 할 일

1. merge된 develop 코드와 위 문서를 읽는다. 저장소는 읽기만 한다
2. 수정안을 파일 전체 내용으로 만든다. 허용 경로는 `기능/<대상 기능>.md`(create 또는 update)와 허브 파일 `$hub`(update)뿐이다
   - 기능 노트 형식을 지킨다: 이 기능이 하는 일 / 현재 처리 흐름 / 예외와 지켜야 할 조건 / 개선 가설과 확인 조건 / 연결 기술 / 코드와 기획 근거 / 확인 이력
   - 확인 이력에 한 줄 추가: 날짜 $today, PR #$pr, 봇 테스트 결과. 실기기·배포는 확인 범위가 아님을 적는다
   - status는 "코드확인". 출시 완료로 쓰지 않는다
   - frontmatter의 필수 키를 지우지 않는다

## 출력

아래 JSON 스키마에 맞는 JSON 객체 하나만 출력한다. 앞뒤에 설명 문장을 붙이지 않는다.
- summary 300자, files 1~5개 {path(볼트 프로젝트 폴더 기준 상대 경로), action(create|update), content(전체 내용)}

$schema

## 금지

- 파일을 직접 만들거나 고치지 않는다. 수정안은 JSON으로만 낸다. 볼트에 쓰는 것은 봇이다
