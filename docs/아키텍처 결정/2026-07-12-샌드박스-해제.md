# 샌드박스 해제 — Accessibility 창 제목 감지

## 상태

승인됨 (2026-07-12)

## 배경

학습 모니터링 기능은 사용자가 딴짓(예: 유튜브 시청)을 하는지 감지하기 위해 전면(foreground) 앱의
창 제목을 읽어야 한다. 예를 들어 브라우저 창 제목이 "동영상 제목 - YouTube" 형태일 때 이를
파싱해 학습 이탈 여부를 판단한다.

이 창 제목 읽기는 `AXUIElement` 기반 Accessibility API로만 가능한데, 이 API는 App Sandbox와
호환되지 않는다. 손쉬운 사용(Accessibility) 권한은 애초에 샌드박스 앱에 부여할 수 없으므로,
샌드박스를 유지한 채로는 이 기능을 구현할 방법이 없다.

## 결정

`ZeroSync/ZeroSync.entitlements`의 `com.apple.security.app-sandbox` 값을 `false`로 변경하여
App Sandbox를 해제한다.

배포 방식은 기존 계획대로 Developer ID 서명 + notarized `.dmg`를 유지한다. 이 앱은 원래부터
Mac App Store가 아닌 Xcode Archive → notarized `.dmg` 경로로 배포되므로, 샌드박스 해제로 인해
Mac App Store 제출이 불가능해지는 점은 감수 가능한 손실이다.

## 대안 검토

1. **축소 모드만 제공 (앱 이름 + 유휴 시간만 감지)**
   샌드박스를 유지하고 `NSWorkspace`의 전면 앱 정보(번들 ID, 앱 이름)와 유휴 시간만으로 감지
   범위를 축소하는 방안. 그러나 브라우저 탭 단위의 유튜브 감지 등 핵심 기능을 구현할 수 없어
   기각.

2. **화면 캡처 + OCR**
   창 제목 대신 화면을 주기적으로 캡처하고 OCR로 텍스트를 추출하는 방안. 개인정보 노출 범위가
   창 제목보다 훨씬 크고(화면 전체 내용), 배터리·CPU 부담도 커서 상시 모니터링 용도에 부적합하여
   기각.

## 영향

- **기존 보안 범위 북마크 유실**: 샌드박스를 끄면 `UserDefaults.standard`의 저장 위치가
  `~/Library/Containers/<번들ID>/...`에서 `~/Library/Preferences/<번들ID>.plist`로 바뀐다.
  따라서 `WorkspaceAccess`가 UserDefaults에 저장해 둔 기존 보안 범위 북마크는 유실되고,
  사용자가 Obsidian vault·Developer 폴더를 다시 선택해야 한다. 출시 전 개인 개발 단계이므로
  감수 가능하다고 판단했다. 북마크 저장·복원 코드 자체는 비샌드박스에서도 동작하므로 코드
  변경은 필요 없다.
- **보안 트레이드오프**: 샌드박스 제거로 앱은 TCC 보호 폴더를 제외한 전체 사용자 파일시스템에
  접근할 수 있게 되고, 손쉬운 사용 권한을 받으면 모든 앱의 창 제목(민감한 문자열이 포함될 수
  있음)을 읽게 된다. 수용 근거: 이 앱의 LLM은 로컬 Ollama(localhost:11434)이므로 창 제목이나
  파일 내용이 외부로 전송되지 않는다.
- hardened runtime은 notarization에 필수이므로 계속 유지되며, 이것이 남은 OS 수준 방어선이다.
- **엔타이틀먼트 정리**: 샌드박스가 꺼진 상태에서는 `network.client`,
  `files.user-selected.read-only`, `files.bookmarks.app-scope` 엔타이틀먼트가 모두
  무의미(inert)하므로 제거하고 `app-sandbox=false`만 남긴다. 추후 샌드박스를 다시 켜려면
  `network.client`, user-selected 파일 접근, `bookmarks.app-scope` 엔타이틀먼트를 복원해야
  한다.
- 손쉬운 사용 권한 요청 UX(권한 안내, 설정 앱 딥링크 등)는 Phase 1 Task 5에서 별도로 처리한다.
- Mac App Store 배포 경로는 이 결정으로 인해 포기한다.
